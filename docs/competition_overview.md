## 2. 평가 방식 (Evaluation)

### 2.1 평가지표: **Macro F1-Score**
본 대회는 타겟 클래스 간 불균형(특정 등급 편중)이 매우 심한 다중 분류 문제이므로, 소수 등급에 대한 분류 성능까지 동등한 비중으로 평가하기 위해 **Macro F1-Score**를 사용합니다.

$$\text{Macro F1} = \frac{1}{K} \sum_{k=1}^{K} \text{F1}_k, \quad \text{F1}_k = \frac{2 \cdot \text{Precision}_k \cdot \text{Recall}_k}{\text{Precision}_k + \text{Recall}_k} \quad (K = 5,\; k \in \{A, B, C, D, E\})$$

- 전체 정확도(Accuracy)가 높더라도 소수 클래스(`A`, `B` 등)의 F1 점수가 낮으면 Macro F1 점수가 크게 하락합니다.
- 학습 손실함수(Multi-class Logloss / Focal Loss / Class Weight)와 **추론 후 확률 임계값·클래스 사전확률 조정(Threshold / Prior Post-processing)**의 분리가 핵심 전략 포인트입니다.

### 2.2 리더보드 산정 비율
| 구분 | 반영 데이터 비율 | 설명 |
| :--- | :---: | :--- |
| **Public Score** | 테스트 데이터의 **50%** | 대회 진행 중 실시간 리더보드 확인용 점수 |
| **Private Score** | 테스트 데이터의 **100%** | 대회 종료 후 **최종 순위 결정 기준** |

> **전략적 유의사항**: Private Score가 테스트 데이터 100%(Public 50% 포함 전체)로 채점되므로, Public LB에 과적합(Overfitting)되는 무리한 제출 튜닝을 피하고 **신뢰할 수 있는 로컬 교차검증(Local CV)** 점수를 최우선 기준으로 삼아야 합니다.

### 4.3 핵심 기술적 난제 (Modeling Challenges)
1. **동일 고객(`ID`)의 다중 월(6개월) 관측 구조 (Group Leakage 위험)**:
   - 한 고객(`ID`)이 `201807`~`201812` 여러 행에 걸쳐 등장합니다.
   - 단순 행(Row) 단위 K-Fold 분할 시 동일 고객의 다른 월 데이터가 Train과 Validation에 동시에 들어가 검증 점수가 비정상적으로 부풀려지는 **Data Leakage**가 발생합니다.
   - **필수 원칙**: 반드시 고객 `ID`를 그룹으로 묶는 **`StratifiedGroupKFold`**(또는 고객 단위 집계 후 고객 단위 **`StratifiedKFold`**)만 사용합니다.
2. **초고차원(870+ 변수) & 대용량 메모리 관리**:
   - 8개 도메인을 단순 `float64`/`object`로 한 번에 병합하면 수십 GB의 RAM을 소모하여 OOM(Out-Of-Memory)이 발생할 수 있습니다.
   - 상수 컬럼(분산 0)·완전 중복 컬럼 사전 제거, 수치형 `float32`/`int32`/`int16` 다운캐스팅, 범주형 `category`/정수 인코딩, 도메인별 선택적 병합 및 중간 Parquet 캐싱(`data/interim/`)이 필수입니다.
3. **극심한 클래스 불균형과 Macro F1 최적화**:
   - 다수 클래스(`E`) 위주로 예측하면 Accuracy는 높지만 소수 클래스(`A`, `B`)의 Recall/Precision이 무너져 Macro F1이 낮게 나옵니다.
   - OOF(Out-Of-Fold) 예측 확률 행렬 `(N, 5)`에 대해 클래스별 승수(Multiplier) 또는 임계값(Threshold)을 최적화(Nelder-Mead / Powell / Optuna 등, 단 반드시 CV 내부에서 중첩 검증)하는 후처리가 매우 큰 성능 향상을 줄 수 있습니다.

  - 본 대회에서 공식 제공한 데이터 외의 **어떠한 외부 데이터(거시경제 지표, 외부 금융 통계 등 포함)도 사용할 수 없습니다.**
